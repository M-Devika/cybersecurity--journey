# Day 01 — ICMP Packet Analysis with Wireshark

## Objective

To understand ICMP communication at the packet level and analyze
ICMP Echo Request and Echo Reply packets using Wireshark.

## Environment

- Operating System: Ubuntu Linux
- Tool: Wireshark
- Network Interface: wlp2s0

## Practical Task

I generated controlled ICMP traffic using:

    ping -c 4 8.8.8.8

I then captured the traffic using Wireshark and filtered the packets
using:

    icmp

## Concepts Learned

- Ethernet II
- MAC addresses
- IPv4
- Source and destination IP addresses
- ICMP
- Echo Request
- Echo Reply
- ICMP Type and Code
- Sequence numbers
- Packet encapsulation

## Packet Structure

    Ethernet II
          ↓
        IPv4
          ↓
        ICMP

## Key Observations

- ICMP Echo Request uses Type 8.
- ICMP Echo Reply uses Type 0.
- Source and destination IP addresses reverse between the request and reply.
- Sequence numbers help identify individual ICMP requests and corresponding replies.
- Ethernet provides Layer 2 addressing information.
- IPv4 provides Layer 3 addressing information.
- ICMP provides information about the ICMP message.

## Investigation Lesson

A packet capture can contain traffic beyond the traffic intentionally
generated by the analyst.

Therefore, packet captures from real networks should be reviewed for
sensitive information before being shared publicly.

## Conclusion

This exercise helped me move from simply using the ping command to
understanding the packet-level communication behind it.

I also learned how Wireshark can be used to inspect network traffic
and investigate communication using packet-level evidence.
